# A 股上市公司财务质量与选股分析系统

> 基于公开财经数据接口，构建 **数据采集 → 数仓分层 → SQL 分析 → 机器学习建模 → API 服务 → 可视化看板** 的完整数据链路。
> 从 5000+ 家 A 股上市公司的真实财报数据中，量化回答「哪些行业真正赚钱」「哪些公司财务质量高」「高股息率公司有什么共同特征」。

## 📌 这个项目解决什么问题

A 股有 5000 多家上市公司，财报数据公开但极其分散、口径不一。投资者和求职者想回答下面这些问题，通常只能靠零散的自媒体文章：

| 问题 | 本文档章节 | 用到的技术 |
|---|---|---|
| Q1 哪些行业盈利能力最强？行业间的 ROE 差距有多大？ | [行业质量分层](#) | SQL 聚合 + pandas 分组 |
| Q2 一家公司"财务质量高"能否被量化打分？ | [质量评分模型](#) | 特征工程 + 加权评分 |
| Q3 营收增长率能否用财务指标预测？ | [回归建模](#) | scikit-learn + 交叉验证 |
| Q4 高股息率公司有哪些共同的财务特征？ | [股息分析](#) | 分类模型 + 特征重要性 |

## 🗂 数据来源

| 数据源 | 内容 | 规模 | 说明 |
|---|---|---|---|
| [东方财富公开数据接口](https://data.eastmoney.com/) | 上市公司业绩报表（ROE / 营收 / 净利润 / 毛利率 / 股息率 / 增长率 / 行业分类） | 2 个报告期，1000+ 条记录（可扩展至全市场 11000+ 条） | 公开接口，无需登录 |

| 字段 | 含义 | 示例 |
|---|---|---|
| `stock_code` / `stock_name` | 股票代码 / 简称 | `000001` / 平安银行 |
| `report_date` | 报告期 | `2024-12-31` |
| `industry` | 所属行业 | 银行Ⅱ |
| `roe` | 加权平均净资产收益率（%） | 10.08 |
| `revenue_yi` / `net_profit_yi` | 营业总收入 / 归母净利润（亿元） | 1466.95 / 445.08 |
| `revenue_yoy` / `profit_yoy` | 营收 / 净利同比（%） | -10.04 / -3.90 |
| `gross_margin` | 销售毛利率（%） | — |
| `dividend_yield` | 最新股息率（%） | 2.04 |
| `net_margin` | 净利率（%，派生字段） | 30.34 |

### ⚠️ 合规声明

本项目**只使用公开、无需登录的数据接口**，并且：

- ❌ 不抓取任何需要登录的网站
- ❌ 不绕过任何验证码、风控或反爬机制
- ❌ 不采集、不存储任何个人信息
- ✅ 已实现请求限速（默认 1 秒/次）与指数退避重试，避免对数据提供方造成压力
- ✅ 原始数据落盘缓存，重复运行不重复请求

> 项目开发过程中，行情接口曾对我们的请求源做 IP 限流。
> **我们的应对是改用公开的财务接口 + 完善缓存层，而不是设法绕过限制。**
> 完整排查过程与经验总结见 [`docs/notes/02-排查记录-接口限流.md`](docs/notes/02-排查记录-接口限流.md)。

## 🚀 快速开始

### 1. 环境要求

- Python 3.12+
- 无需数据库服务（使用 SQLite 文件库）

### 2. 安装

```bash
git clone https://github.com/<你的用户名>/job-market-intel.git
cd job-market-intel

# 创建虚拟环境
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

### 3. 先做数据源健康巡检（推荐）

```bash
python scripts/00_health_check.py
```

会输出各数据源的可用状态，并生成 `docs/notes/数据源巡检报告.md`。
**先确认数据源活着，再跑采集**——这是我踩坑之后加上的习惯。

### 4. 采集数据

```bash
# 小规模验证（只抓 1 页，约 500 条）
python scripts/02_collect_finance.py --report-date 2024-12-31 --max-pages 1

# 全量采集（2024 年报 + 2025 半年报，约 1000+ 条）
python scripts/02_collect_finance.py

# 忽略缓存强制重新采集
python scripts/02_collect_finance.py --no-cache
```

采集完成后，数据会同时写入：
- `data/processed/ods_finance_performance.csv`（可直接用 Excel 打开）
- `data/jmintel.db`（SQLite，表名 `ods_finance_performance`）

### 5. 用 SQL 检查数据

```bash
sqlite3 data/jmintel.db "SELECT industry, COUNT(*) AS 公司数, ROUND(AVG(roe),2) AS 平均ROE FROM ods_finance_performance GROUP BY industry ORDER BY 平均ROE DESC LIMIT 10;"
```

## 📊 工程要点（面试可讲的亮点）

### 1. 分层架构，而不是一个大脚本

`config` 管配置、`http` 管网络、`cache` 管缓存、`storage` 管落地、`sources` 管数据源。
新增一个数据源只需在 `sources/` 下加一个文件，**不改动任何已有代码**。

### 2. 取数与解析分离

网络请求是稀缺资源（会被限流），解析逻辑却经常要改。
两者分离后，修改解析逻辑可以直接用本地缓存重跑，**不需要重新请求接口**。

### 3. 指数退避重试 + 请求限速

```python
wait = 2 ** (attempt - 1)   # 1s → 2s → 4s，给对方服务器恢复时间
```

失败重试不是"立刻重试"，而是逐渐拉长间隔——这比固定间隔成功率更高。

### 4. 原始数据落盘 + 原子写

```python
tmp.write_text(...)   # 先写临时文件
tmp.replace(path)     # 再原子替换，避免中断产生半截文件
```

### 5. 故障隔离

单个报告期采集失败**不会中断**其他报告期的采集（`scripts/02_collect_finance.py`）。
一条流水线不应该因为一个数据源挂掉就整体崩溃。

### 6. 幂等性

`if_exists="replace"` + `drop_duplicates()` 保证**重复运行结果一致**，
这是数据管道的基本要求。

### 7. 数据质量标记而非直接删除

对异常值（净利润为负、ROE 极端值、关键字段缺失）打标记列而不是删除，
因为"哪些公司异常"本身就是分析素材，删除还会导致公司总数与财报披露数对不上。
