## 一、一句话定位

**「企业经营与就业市场情报分析系统」**
——基于公开财经数据接口，构建从数据采集、数仓分层、SQL 分析、机器学习建模到接口服务与可视化的完整数据链路。

**英文仓库名**：`job-market-intel`（GitHub 上看起来专业、好记、好念）

## 二、它回答什么业务问题？（这是项目的灵魂）

一个只会写代码的项目是"作业"，能回答业务问题的项目才是"项目"。

本项目回答 4 个真实问题（而且都是你求职时会用到的）：

| 编号 | 业务问题 | 用到什么技术 | 为什么面试官感兴趣 |
|---|---|---|---|
| Q1 | 哪些行业在扩张、哪些在收缩？企业财务表现如何分层？ | SQL 聚合、pandas 分组、财务指标计算 | 体现业务理解 |
| Q2 | 行业景气度能不能用财务指标自动判别？ | 分类模型 + 特征重要性 | 体现建模能力 |
| Q3 | 公司盈利能力（ROE）能被哪些指标预测？ | 回归模型 + 交叉验证 + 误差分析 | 体现实验方法论 |
| Q4 | 求职者应该往哪些行业/地区投？ | 多维分析 + 可视化看板 | **能讲出结论和建议** |

> **关键点**：Q4 是整份简历里最亮的一笔——
> 你不仅做了技术，还**用数据给出了自己的求职决策依据**。
> 面试官会对"你从数据里发现了什么"印象极深。

## 三、数据来源（必须能一句话说清，且必须是真实的）

| 数据源 | 内容 | 规模 | 合规性 |
|---|---|---|---|
| 东方财富公开行情接口 | A股上市公司行情、估值、行业、地域、概念标签 | 5500+ 家 | 公开接口，无需登录 |
| 东方财富公开财务接口 | ROE、EPS、营业收入、净利润 | 5000+ 家 / 年 | 公开接口 |
| Remotive 公开岗位 API | 真实远程岗位（含薪资字段、技能标签） | 按需调用 | 官方开放 API，明确允许调用 |

**明确不做的事**（写进 README，反而是加分项）：
- ❌ 不抓取需要登录、有强反爬的招聘网站
- ❌ 不绕过任何验证码 / 风控机制
- ❌ 不采集、不存储任何个人信息

> **面试话术**：
> "我评估过抓招聘网站，但它们有 WAF 和加密参数，属于明确的反爬机制。
> 我判断投入产出比不合理，而且合规风险高，所以改用了公开财经接口 +
> 官方开放的岗位 API。**这个取舍本身就是工程判断。**"

这段话直接展示了你**有技术判断力和合规意识**，比"我爬了 10 万条数据"更值钱。

## 四、技术栈总览

| 层次 | 技术 | 说明 |
|---|---|---|
| 数据采集 | requests + Session + 重试/限速 | 自研轻量采集框架 |
| 数据存储 | SQLite + 分层目录（raw/interim/processed） | 数仓分层思想 |
| 数据处理 | pandas / numpy | 清洗、类型转换、派生字段 |
| 数据分析 | SQL（窗口函数、CTE）+ pandas | 多维度业务分析 |
| 机器学习 | scikit-learn | 分类 + 回归 + 交叉验证 + 特征重要性 |
| 模型服务 | FastAPI + uvicorn | REST API + 自动文档 |
| 可视化 | matplotlib / seaborn + Streamlit | 静态图 + 交互看板 |
| 工程化 | git / logging / pytest / argparse / .gitignore | 让人相信这是工程而非作业 |
| 部署（进阶） | Docker | 一键复现环境 |

## 七、面试 3 分钟自述稿（W8 定稿，现在先看框架）

```
【1. 动机 · 15秒】
我大三在找数据方向实习，想知道数据类岗位到底集中在哪些行业、
什么类型的公司更值得去。市面上的分析报告要么过时要么没有原始数据，
所以我决定自己采集真实数据来回答这个问题。

【2. 数据 · 20秒】
我用的是公开财经接口，覆盖 5500 多家 A 股上市公司的行情、估值、
行业分类和财务指标，另外接了 Remotive 的公开岗位 API 做交叉参考。
我主动放弃了抓取招聘网站，因为它们有 WAF 和加密参数，
合规风险和投入产出比都不划算。

【3. 架构 · 40秒】
工程上我做了分层：config 管配置，http 层统一处理超时、重试和限速，
sources 是数据源适配器，storage 负责数据落地。
数据分三层：raw 层原样保留接口响应，processed 层是清洗后的规范表，
最后进 SQLite 支撑 SQL 分析。
我特意把"取数"和"解析"拆开，因为解析逻辑经常要改，
拆开后可以直接拿本地原始数据重跑，不用反复请求接口——
对方服务器的压力小，我的迭代速度也快。

【4. 建模 · 40秒】
建模部分我做了两件事：一是用财务指标判别行业景气度，
二是预测公司 ROE。我先跑了线性回归做基线，
然后用随机森林和梯度提升对比，用 5 折交叉验证选参数。
最后 R² 从 x.xx 提升到 x.xx。
我还做了特征重要性分析，发现 xx 是最强的预测因子，
这符合业务直觉，因为……

【5. 工程与结论 · 40秒】
交付上我做了 FastAPI 接口和 Streamlit 看板，写了单元测试，
用 Docker 保证一键复现。
分析结论上，我发现……（讲 1-2 个真实发现）
基于这个结论我调整了自己的投递策略。

【6. 反思 · 25秒】
这个项目最大的难点是 xx。我一开始的做法是 xx，
后来发现 xx 问题，改成了 xx。
如果继续做，我会补充 xx——比如引入时间维度做趋势分析。
```

**注意第 6 段的"反思"**：面试官最看重这个。
能说出自己方案的**不足**，说明你真的思考过，而不是抄的。
